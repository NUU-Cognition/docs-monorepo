---
title: "Quick Start: Your First Flint"
---

This guide takes you from the install to your first Flint and your first agent session. You need no NUU account and no org.

## Prerequisites

You need:

- Node.js with `npm`
- Git
- a terminal where global installs are allowed
- Obsidian, if you want it (it is optional)

## Step 1: Install the CLI

```bash
npm install -g @nuucognition/flint-cli
flint --version
```

The package installs two commands: `flint` and `nuu`. You type `flint`. `nuu` manages the identity of this machine and the network; most people never type it.

To see if a newer release exists later:

```bash
flint update --check
```

## Step 2: Set Up This Machine

```bash
flint setup
```

`flint setup` needs internet access. With no network it stops before the first step. It runs seven steps in order:

1. **Identity**: your Name and the machine display name.
2. **Git author**: the author of the first commits of new Flints.
3. **Environment**: a check of Git, Node.js, Obsidian, and the agent CLIs.
4. **Agent default**: the first copy of the Orbh profiles and the default target list.
5. **Computer Flint**: the home Flint of this machine.
6. **Guide**: a clone of the Guide of NUU Cognition (optional).
7. **Open and onboarding**: the open of the Computer Flint with your first agent session.

For the full detail of each step, read [Setting Up a Machine](/flint/guide/setting-up-a-machine). To change your Name only later, run `flint config name "<Name>"`. Login and an org stay optional; to share Flints with an org, read [Join Your Org](/flint/guide/join-your-org).

## Step 3: Create a Flint

```bash
flint create "My Notes"
```

`flint create` makes the folder `(Flint) My Notes` in the current folder. (`flint init` is an alias of `flint create`.) The screen tells you what you have.

```text
✓ Created the Flint My Notes
  Address  : @/flint/my-notes (local: no org, this machine only)
  Path     : ~/notes/(Flint) My Notes
  Shards   : invironments, flint, orbh (preset blank)
  Git      : a local repository (no remote)
  Obsidian : payload 0.7.0 installed · opened
             Click "Trust author and enable plugins" once in Obsidian.
Next: flint open "My Notes"
Or start an agent: cd '/home/ada/notes/(Flint) My Notes' && flint orbh i
Later: flint git publish <url>
```

An address that starts with `@/` names no org. It works only on this machine. To share the Flint, give it an org: `flint org set <org>`.

Useful variants:

```bash
flint create "My Notes" --preset default   # More shards: Projects, Notepad, Plan, Increments, Reports, Agents, Claude Code
flint create "My Notes" --path ~/notes      # Make the Flint in another folder
flint create --from <git url>               # Clone a Flint from a Git repository
flint create "My Notes" --no-obsidian       # Skip Obsidian for this run only
```

A preset is the list of shards of a new Flint. `blank` is the default: only the core shards (Flint and Orbh; Invironments comes with Flint). `flint create --help` lists the presets. For the full detail, read [Creating a Flint](/flint/guide/creating-a-flint).

If the network is down, `flint create` still makes the Flint. It names each part that it did not install, and it prints the one next command that installs the missing parts.

## Step 4: Open the Flint in Obsidian

In a terminal, `flint create` already installs the Obsidian payload and opens the Flint in Obsidian. Obsidian asks once for the new vault: click **Trust author and enable plugins**. To open or focus the Flint later, run:

```bash
flint open "My Notes"
```

Flint needs no one editor: the files are plain Markdown. For the payload, the applied settings, and the backups, read [Using Obsidian](/flint/guide/using-obsidian).

Now move into the Flint:

```bash
cd "(Flint) My Notes"
```

A new Flint holds `Mesh/` for your notes, `Media/` for files that are not Markdown, `Shards/` for the programs that agents load, and `Sources/`, `Workspace/`, and `.flint/` for outside material, active repositories, and the facts of this machine.

Open `Mesh/(System) Flint Init.md`. This note tells humans and agents what the Flint is for. A new Flint has a starter note; in the first agent session, the agent asks you what the Flint is for and rewrites the note.

## Step 5: Add a First Note

Create a note in `Mesh/`:

```markdown
---
id: 11111111-1111-1111-1111-111111111111
tags:
  - "#note"
---

# Project Ideas

Initial thoughts for the project.

## Goals

- Keep architecture notes close to the codebase
- Track follow-up tasks in one place
```

Three habits help from the start: use frontmatter in each note, use tags on purpose, and link related notes with `[[wiki links]]`.

## Step 6: Sync After a Change

When you change `flint.toml`, run:

```bash
flint sync
```

`flint sync` makes the files of this Flint match its lock and its declarations. It installs missing shard builds and the pinned Obsidian payload. It never reads the shard registry and never pushes or pulls Git. For the full detail, read [Sync](/flint/modules/sync).

When you add or change a shard spec in `flint.toml`, run `flint shard install` first. It makes the lock match the specs. To exchange history with origin, run `flint git sync`.

## Step 7: Start an Agent Session

From inside the Flint, run:

```bash
flint orbh i
```

This starts an interactive agent session with Orbh session tracking. With no target, Orbh uses the default target list and selects the first target that can run. If no target can run, it prints the one install command that makes one available. For the full detail, read [Agent Sessions](/flint/modules/agent-sessions).
