---
title: "Set Up a Project"
---

This guide shows you how to create a project and give it structure. At the end you have a project with a backlog, one or more deliverables, and sections for the work.

## Prerequisites

- You are signed in with your NUU account.
- You have an active workspace. Use your personal workspace, or an organisation you belong to. See [About Workspaces](/operations/concepts/about-workspaces).

## Open the workspace

Switch to the workspace that should own the work. Organisation work belongs in an organisation. Personal work belongs in the personal workspace.

Open the project list for that workspace.

## Create the project

Create a project. Give it a name. You can add a next-update date. That date is optional. It is a reminder for the project. It is not a deadline.

The new project is active. Open it.

The project page is one page. It shows what you need to do the work:

- the name, the status, and the description at the top
- the sections of the project, with the backlog first
- the deliverables, each with its sections, its progress, and its done button
- the deployments

Activity is in the More menu of the project.

You can attach a deadline to the project now, or later. The date lives on the deadline. See [Plan Your Week](/operations/workflows/plan-your-week).

## Give the project context

Open the edit sheet of the project. Fill in the Context field: what this is about, for search and suggestions. Write a short paragraph in Markdown. Name the product, its goals, the people it is for, and the words that people use for it.

The page does not show the context. Search and smart suggestions read it. A good context helps a new task find this project.

## Capture work in the backlog

The project has one backlog section. The service makes it the first time the project needs it. Put work there that is not committed yet.

In the backlog, tasks sort by priority, then by order.

## Add deliverables

Create a deliverable for each scoped outcome. Give it a title. You can give it a date at creation. If you do, the service creates a deadline for it.

A new deliverable is empty. The service makes no section and no task for it. Add the sections yourself. See [Plan Work with Sections](/operations/guides/plan-work-with-sections).

Do not put every outcome in one deliverable. The graph works better when each deliverable is one chunk.

A workspace-wide deliverables list also shows these rows across projects. You can search that list by deliverable name or by project name.

## Add project sections

Some work has no deliverable yet. You can still name it. Add a section to the project itself. Add tasks to it.

When you scope a deliverable later, move the section into it. See [Move Tasks](/operations/guides/move-tasks).

## Add a deployment

If the project runs something, for example a site, an app, or a service, add a deployment to the project. See [Run a Deployment](/operations/guides/run-a-deployment).

## Check what you have

Open the project. You should see the backlog, the project sections, and the deliverables. Open a deliverable. You should see its sections. The deliverable is open. It stays open until a person marks it done with its done button.

You can rename the project. You can rename a deliverable.

You can delete a project or a deliverable. Deleting a deliverable removes its sections and its tasks. Do that only when the chunk is wrong.
