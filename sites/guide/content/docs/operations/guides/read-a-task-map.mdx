---
title: "Read a Task Map"
---

This guide shows you how to read the task map of a task. The task map shows where a task sits and how it connects to other work. At the end you know the tree of the task, its home, its groups, and its history.

## Prerequisites

- You have a task. See [About Tasks and Backlogs](/operations/concepts/about-tasks-and-backlogs).

## Open the task map

Open the task. Open its task map.

The map has five parts: the tree, the home, the groups, the lineage, and the related tasks.

## The tree

The tree shows the root task and all the subtasks under it. The task that you opened is marked in the tree.

If you opened a subtask, the tree starts at its root task. So you always see the whole tree.

Each task in the tree shows its state. The root task shows how many of its subtasks are done.

To add a subtask, open the task that should hold it, and add a subtask there. A tree can be at most six levels deep.

## The home

The home shows where the task lives:

- the project
- the deliverable, when the task is in a deliverable
- the section
- the deployment, when the task is in the inbox of a deployment

A subtask has the home of its root task. Choose a part of the home to go there.

## The groups

A task can be in task groups. A task group collects tasks that belong together, across sections and projects. The map lists each group of the task with its members.

## The lineage

The lineage shows where the task came from and where its work went:

| Link | Meaning |
| --- | --- |
| Split from | This task was split out of another task. |
| Merged into | This task was merged into another task. |
| Continues from | This task continues the work of an earlier task. |
| Continued by | A later task continues the work of this task. |
| After | This task comes after these tasks. |
| Before | This task comes before these tasks. |

A split, a merge, or a continue never deletes a task. The old task closes as superseded, and the link keeps the history.

Use the lineage to follow a piece of work over time, when it moved through more than one task.

## Related tasks

Related tasks are other tasks that are linked to this task. The link has no order and no history. Use it for work that touches the same thing.

## What the task page shows

The task page shows what you need to do the work: the title, the state, the owner, the description, the subtasks, and the comments.

The description is Markdown. You read it formatted. You edit it in the same editor that notepads use.

Activity is behind a tab or a link. Developer panels, such as repositories and commits, are not on the default page.
