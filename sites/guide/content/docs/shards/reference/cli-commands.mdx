This page reflects the current command surface in `apps/flint-cli/src/index.ts` and the command modules it mounts. `flint orbh` mounts the shared Orbh command tree from `apps/orbh-cli/src/` and adds Flint path resolution plus `flint orbh artifact`.

## How to Read the CLI

Global flags:

- top level: `-V, --version`, `-h, --help`
- every Commander subcommand also accepts `-h, --help`
- commands that operate on a Flint usually accept `-p, --path <dir>` or `--path <dir>`; commands that manage global state do not

If you are new to Flint, the most important starting commands are still:

```bash
flint init
flint sync
flint shard list
flint whoami
```

Dev-gated commands are present in the dev binary and hidden in production mode unless the feature gate allows them.

- `-p, --path <dir>`

### `flint register [path]`

- `-f, --force`

### `flint unregister [path]`

Remove a Flint from the global registry without deleting files.

- `-f, --force`

### `flint delete [name-or-path]`

Permanently delete a Flint folder and registry entry. Treat this as destructive.

- `-f, --force`

### `flint move <name-or-path> <destination>`

Move a Flint and update the registry.

- `-f, --force`
- `-y, --yes`

### `flint sync`

Sync the workspace against `flint.toml`.

- `-p, --path <dir>`
- `--migrate`

### `flint gigasync`

Run `git sync` -> `obsidian update` -> `shard update` -> `sync`, stopping on the first failure.

### `flint plan`

Show what `flint push` would do as a drift report only.

- `--apply`

### `flint registry`

Validate the global Flint registry.

- `validate` flags: `--dry-run`, `--json`

### `flint update`

Check for or install the latest `@nuucognition/flint-cli`.

### `flint tinderbox`

Orchestrate multiple Flints (and shared codebases) as one declared, git-versioned box. A Tinderbox is a directory with a `tinderbox.toml` that declares member Flints (`[flints]`), shared repos (`[repos]`), and cross-Flint connections (`[connections]`). Members are declared in **own** mode (cloned from a git URL into a folder under the box) or **reference** mode (`registry:Name` — point at the existing registered copy instead of cloning), and as `required` (missing → error) or `optional` (missing → warning, for remotes a machine cannot reach).

All `flint tinderbox` subcommands use walk-up discovery to find `tinderbox.toml`, so they run from the Tinderbox root or from inside any member Flint.

**Lifecycle subcommands:**

- `init <name>` — bootstrap an empty Tinderbox in the current directory
- `init --from <url>` — clone an existing Tinderbox from a git remote and sync it (name is read from the cloned `tinderbox.toml`)
- `start <name> [path]` — promote the current Flint into a new Tinderbox, moving it under the box root
- `import <name> [source]` — physically MOVE a registered Flint into this box (confirmed unless `--yes`); if `<name>` is not registered and a `source` is given, declare it by URL / `registry:Name` instead. Supports `--no-open`.
- `add <name> <source>` — declare a Flint by git URL (own) or `registry:Name` (reference) without materializing it; the next `sync` clones or references it
- `remove <name>` — eject a member: undeclare it and strip its wiring while keeping it registered (inverse of `import`); `--move-out <dir>` relocates the folder out of the box
- `rename <from> <to>` — rename a member Flint, cascading the change to `[connections]`, `[repos].exposed-to`, the folder, the registry, and fulfillments; `--tinderbox <new-name>` renames the Tinderbox itself
- `dissolve` — tear down the box: eject every member (folders are preserved), strip wiring, and remove `tinderbox.toml`; `--move-to <dir>`, `--force`, `--yes`

**Sync and drift:**

- `sync` — materialize declared members (clone own-mode, reference registry-mode, adopt/relocate a registry match after verifying its remote), register them in Obsidian, and wire connections and repos. Flags: `--dry-run`, `--json`, `--full` (also run `flint sync` in each member), `--only <names...>` / `--skip <names...>`, `--no-open`, and the undeclared-deletion controls `--yes` / `--delete-undeclared` / `--force`.
- `status` — per-member mode, tier, present, registered, and connection-fulfillment state, plus a Repos section; supports `--json`
- `check` — read-only drift detection between `tinderbox.toml` and disk (undeclared/missing/renamed members, broken materialization, stale registry/connection/repo wiring); exits 1 on any drift; supports `--json`
- `heal` — auto-fix drift by rewriting `tinderbox.toml` and then running a full sync; previews the plan and confirms first (`--dry-run`, `--yes`)

**Repos and connections:**

- `repo add <name> <source>` — clone a git repo into `Repos/` (or `path:<dir>` for reference mode) and expose it to member Flints; `--exposed-to <all|names>`, `--mode <own|reference>`
- `repo remove <name>` — drop a repo declaration and strip references from exposed Flints; `--purge` deletes the clone (confirmed unless `--yes`)
- `repo list` — list declared repos: name, mode, location, present, exposed-to
- `connection add [from] [to]` — declare a directional connection, or an interconnected group with `--group <names...>`
- `connection remove [from] [to]` — remove a connection and strip the wired references from child Flints (also accepts `--group`)
- `connection list` — list declared connection edges and whether each is wired

**Git and identity across the box:**

- `git sync` — sync the Tinderbox repo and run `flint git sync` in every member Flint
- `git publish <url>` — add a remote and push the box's initial commit; force-renames the branch to `main` and auto-commits pending changes (warns/confirms unless `--yes`)
- `whoami <name>` — propagate the person identity to every member Flint

## Practical Advice

For everyday work, think in terms of a few dependable loops:

- `init` to create the environment
- `sync` to materialize declared capabilities and dependencies
- `orbh` to run the work
- `export` to publish results

That sequence matches Flint's actual shape as a workspace where agents execute cognitive programs and leave durable artifacts behind.
